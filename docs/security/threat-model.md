# MDIS Security Threat Model and Review

**Review date:** 2026-10-07  
**Scope:** Authentication and sessions, role and organization authorization, upload and processing, review/export, audit, browser client, provider configuration, and deployment settings.  
**Method:** Adversarial source review plus the repository's automated tests. This is not a penetration test, a compliance determination, a clinical evaluation, or a review of a live production deployment.

## STRIDE threats

| STRIDE category / threat | Attack | Current mitigation in code | Evidence / test |
|---|---|---|---|
| Spoofing: credential stuffing and brute force | Reuse leaked credentials or guess passwords across accounts/IPs | Argon2id password hashes, generic login failure, per-IP and per-account database rate buckets, progressive non-admin lockout, mandatory MFA for admin/operator | `test_authentication.py` generic login, Argon2id and MFA tests; `test_auth_phase2.py` per-IP/account limits and lockout tests |
| Spoofing: account enumeration | Compare login, reset, or invitation responses for known and unknown accounts | Login does dummy Argon2 work and returns the same status/detail; reset uses a generic response and minimum response floor; invitation acceptance uses opaque hashed single-use tokens | Login parity in `test_authentication.py`; reset generic and single-use in `test_auth_phase2.py`. A statistically reliable production timing comparison is not established by these functional tests. |
| Tampering: JWT modification | Change claims, expiry, audience, issuer, or algorithm | Algorithm pinned to HS256; required `iss`, `aud`, `exp`, `iat`, `sub`, `jti`; database user/session check | Expiry tests plus Phase 5 `alg=none` and wrong-audience tests in `test_authentication.py` |
| Repudiation: audit denial | Deny or alter a sensitive action without trace | Audit events record action, actor/org/resource identifiers, request ID and sanitized network metadata; database trigger rejects audit updates | Audit metadata and append-only tests in `test_tenant_upload_audit.py`; auth/admin audit tests in `test_auth_phase2.py` |
| Information disclosure: session hijacking/fixation | Steal a session, set a chosen session, or use a revoked session | HttpOnly cookies, Secure outside development, SameSite=Lax, short access token, rotating refresh family, refresh hashes at rest, session existence checked per request, logout revokes the family, no-store API headers | Cookie, refresh rotation/reuse, expiry, logout, and no-store tests in `test_authentication.py`; startup config tests |
| Information disclosure: XSS token theft | Inject script and read credentials from browser storage | Auth tokens are HttpOnly cookies; frontend API client does not expose access tokens; no `dangerouslySetInnerHTML` use found in source scan | `authCookies.test.ts`, source scan. Browser runtime XSS testing was not performed. |
| Information disclosure / elevation: CSRF | Cause a signed-in browser to submit a state-changing request | Double-submit CSRF cookie/header; SameSite cookies; unsafe cookie-authenticated requests validate the pair | Missing-CSRF login test and route inventory CSRF assertions in `test_authentication.py` and `test_role_matrix.py` |
| Tampering / elevation: refresh-token replay | Replay a replaced refresh token to keep an attacker session alive | Refresh tokens stored as hashes; rows lock during rotation; use of revoked token revokes active members of its family | `test_reuse_of_rotated_refresh_token_revokes_family` |
| Elevation: privilege escalation | Claim an admin role in request data or call an admin-only endpoint as another role | Roles are read from the database-backed identity; role dependencies are on API routes; request schemas forbid unknown fields; admin API is org-scoped | Route inventory and role matrix in `test_role_matrix.py`; role-change denial in `test_auth_phase2.py`; unknown login-field test |
| Tampering / IDOR: cross-tenant access | Substitute another tenant's IDs for patient, document, extraction, evidence, review task, processing job, export, or audit data | Tenant context is set from the authenticated user; ORM read criteria and explicit document/patient access checks scope records; inaccessible details return 404 | `test_tenant_upload_audit.py` includes cross-organization patient/document/timeline/entity/evidence/review/job/steps/FHIR/export and operator audit-list checks |
| Denial of service: reset and MFA abuse | Flood recovery, invitation, refresh, or MFA endpoints | Database-backed per-IP/account limits; random single-use action tokens; lockout; MFA verification throttling | `test_auth_phase2.py` rate-limit, reset expiry/reuse, invitation single-use, lockout, and MFA flow tests |
| Elevation / repudiation: insider misuse | Privileged user accesses or changes accounts beyond their organization | Admin APIs constrain user IDs to the admin's organization; audit records role and session changes; self-deactivation blocked | Admin authorization/audit tests in `test_auth_phase2.py`; cross-organization user list/session/role tests in `test_tenant_upload_audit.py` |
| Information disclosure: log leakage | Provider errors, requests, or audit metadata contain passwords, tokens, OCR text, or PHI | Generic client errors; provider logger records only error type; audit metadata is identifier/action-only; database SQL echo is off | Audit metadata assertions, provider error redaction tests; logs of a live deployment were not inspected |
| Elevation / data integrity: fake OCR result | Select a provider that returns a success-shaped placeholder instead of provider output | Azure OCR now polls its same-origin operation URL, returns actual text/confidence, and fails on timeout/error/empty content; startup rejects mock OCR/extraction providers outside development | Azure success/failure/empty/foreign-operation-URL tests in `test_providers.py`; production mock-provider startup test in `test_authentication.py` |

### Explicit additional checks

- **Open redirect:** login `returnTo` accepts only a same-origin relative path and rejects protocol-relative and backslash paths. Tested in `src/test/authCore.test.tsx`.
- **CSRF:** unsafe cookie-authenticated requests require matching CSRF cookie and header; route inventory requires CSRF dependencies for public unsafe auth routes. Tested in `test_authentication.py` and `test_role_matrix.py`.
- **Session fixation:** login creates a new server-generated session family; refresh rotates the secret and reuses the family only for rotation tracking. Login does not accept a client-provided session ID. Rotation/reuse and login cookie tests exist; there is no dedicated fixation test using a pre-login attacker cookie.
- **Production bypass:** backend rejects auth bypass outside development; frontend build rejects `VITE_AUTH_BYPASS` in production. Backend now treats either `APP_ENV` or `ENVIRONMENT` marked production as production. Tests cover those guards; an actual production build environment was not deployed.

## Findings and residual risks

1. **Tenant isolation depends partly on ORM query listeners.** `backend/app/db.py` applies tenant criteria to ORM SELECTs after request identity sets the organization. It is not PostgreSQL row-level security, it does not scope bulk UPDATE/DELETE statements, and intentional unscoped lookup flags exist for authentication/background jobs. The application must not add raw SQL or unscoped data access without explicit scope. Add database row-level security or equivalent transaction-local tenant enforcement and a complete route/service IDOR matrix before production.
2. **Background processing is in-process.** A process crash can strand jobs. Add a durable queue, lease/retry recovery, and worker identity/org-context handling before relying on long-running or critical processing.
3. **Provider/data governance is deployment-specific.** OpenAI/Azure configuration can send document content to external services. Decide and document approved data flows, contracts, retention, region, and egress policy before enabling them for sensitive records.
4. **Local file storage deployment controls are unverified.** This review did not establish encryption at rest, backups, malware scanning, retention enforcement, filesystem permissions, or disaster recovery.
5. **No live production or browser assessment.** No penetration test, production traffic/log review, device matrix, external FHIR-server push, or independent deployment configuration inspection was performed.
6. **Operational alerting is not proven.** Audit rows and rate limiting exist, but alert routing, incident response, monitoring SLAs, and log retention were not exercised.
7. **Potential platform attack surfaces remain.** Add a WAF/rate controls at the edge, SSO/SAML only through a reviewed identity integration, external penetration testing, signing/encryption key rotation procedures, dependency update automation, and incident response exercises.
