# MDIS Clinical Document Evaluation Framework

This directory contains the reference evaluation datasets, ground-truth annotation schemas, baseline metrics, and report outputs for the **Medical Document Intelligence System (MDIS)**.

The framework evaluates:
1. **OCR Quality:** Character Error Rate (CER) and Word Error Rate (WER) comparing raw OCR against ground-truth transcriptions.
2. **Layout & Spatial Grounding:** Bounding Box Intersection over Union (IoU) comparing predicted entity coordinates to gold-standard visual regions.
3. **Clinical Information Extraction (IE):** Precision, Recall, and F1 score calculated:
   - **Per clinical entity type:** `diagnosis`, `medication`, `symptom`, `procedure`, `lab`.
   - **Per clinical document category:** `discharge_summary`, `progress_note`, `emergency_note`, `radiology_report`, `lab_report`.
4. **Assertion & Negation Accuracy:** Evaluating whether clinical concepts are correctly flagged as `present`, `absent` (negated), `possible`, `historical`, `hypothetical`, or `family`.

## Annotation Schema Specification

Annotated documents must conform to [`annotation_schema.json`](file:///c:/Users/Meta/project%20z/Cognate-AI%20main/Cognate-AI/backend/evals/annotation_schema.json) (modeled by `app.evals.schema.AnnotatedDocument`).

### Document-Level Fields
| Field | Type | Description |
|---|---|---|
| `id` | `string` | Unique document identifier (e.g., `"DOC-DISCH-001"`). |
| `category` | `string` | Document category: `discharge_summary`, `progress_note`, `emergency_note`, `radiology_report`, `lab_report`. |
| `ground_truth_text`| `string` | Human-verified gold-standard transcription of the document. |
| `ocr_text` | `string` (optional) | Output produced by the OCR engine (used to compute CER and WER). |
| `entities` | `list` | List of gold-standard clinical entities. |
| `metadata` | `object` (optional) | De-identified metadata (e.g. `encounter_type`, `scan_resolution`, `source_format`). |

### Entity-Level Fields
| Field | Type | Description |
|---|---|---|
| `type` | `string` | Entity category: `diagnosis`, `medication`, `symptom`, `procedure`, `lab`. |
| `text` | `string` | Exact character substring from `ground_truth_text`. |
| `normalized_value` | `string` | Canonical clinical concept name or terminology mapping. |
| `span` | `object` | Character offsets: `{"start_offset": int, "end_offset": int}`. |
| `negated` | `boolean` | `true` if clinically negated (e.g., "denies chest pain", "no fever"). |
| `temporality` | `string` | `current`, `historical`, `hypothetical`, `possible`, `family`. |
| `assertion` | `string` | Mapped MDIS assertion: `present`, `absent`, `possible`, `historical`, `hypothetical`, `family`. |
| `bounding_box` | `list[float]` (optional)| Normalized coordinates `[x_min, y_min, x_max, y_max]` in range `[0.0, 1.0]`. |
| `code` | `string` (optional) | Standard ontology code (ICD-10, RxNorm, SNOMED CT, LOINC). |
| `code_system` | `string` (optional) | Terminology name (e.g., `ICD10`, `RxNorm`, `LOINC`). |

### Minimal Example
```json
{
  "id": "DOC-DISCH-001",
  "category": "discharge_summary",
  "ground_truth_text": "Patient has hypertension. Denies chest pain. Prescribed Metformin 500 mg.",
  "ocr_text": "Patient has hypertension. Denies chest pain. Prescribed Metformin 500 mg.",
  "entities": [
    {
      "type": "diagnosis",
      "text": "hypertension",
      "normalized_value": "Hypertension",
      "span": {"start_offset": 12, "end_offset": 24},
      "negated": false,
      "temporality": "current",
      "assertion": "present",
      "bounding_box": [0.1, 0.2, 0.4, 0.23],
      "code": "I10",
      "code_system": "ICD10"
    },
    {
      "type": "symptom",
      "text": "chest pain",
      "normalized_value": "Chest pain",
      "span": {"start_offset": 33, "end_offset": 43},
      "negated": true,
      "temporality": "current",
      "assertion": "absent",
      "bounding_box": [0.1, 0.25, 0.35, 0.28]
    }
  ]
}
```

## How to Add Annotated Documents (Scaling to 250+ Corpus)

The dataset loader ([`backend/app/evals/loader.py`](file:///c:/Users/Meta/project%20z/Cognate-AI%20main/Cognate-AI/backend/app/evals/loader.py)) is designed to ingest either:
1. **Single JSON files:** e.g., `backend/evals/annotated_samples.json` containing an array of documents.
2. **A Corpus Directory:** A folder (e.g. `backend/evals/corpus/`) containing individual `.json` files (e.g. one file per note, or grouped by batch / category).

### Steps to Add Documents:
1. **De-identification & Consent:** Ensure all documents are de-identified in strict adherence with HIPAA Safe Harbor or Expert Determination requirements. Never commit raw PHI.
2. **Save Document Files:**
   - Either add documents to `backend/evals/annotated_samples.json`, or
   - Place individual files under `backend/evals/corpus/` (e.g., `DOC-001.json`, `DOC-002.json`).
3. **Validate Format:**
   Validate your JSON files against [`annotation_schema.json`](file:///c:/Users/Meta/project%20z/Cognate-AI%20main/Cognate-AI/backend/evals/annotation_schema.json).
4. **Execute Evaluation:**
   Run the evaluation script against your new corpus:
   ```bash
   python backend/app/evals/run_eval.py --dataset backend/evals/corpus
   ```

## Running Evaluations & Managing Baselines

### 1. Evaluate the Default Fixtures
```bash
python backend/app/evals/run_eval.py
```

### 2. Evaluate Reference Samples
```bash
python backend/app/evals/run_eval.py --dataset backend/evals/annotated_samples.json
```

### 3. Evaluate Full 250+ Corpus Directory
```bash
python backend/app/evals/run_eval.py --dataset backend/evals/corpus/
```

### 4. Check for Regression Against Baseline
```bash
python backend/app/evals/run_eval.py --check-baseline
```
Exits with code `1` and prints the drop details if any metric fell below `baseline.json`.

### 5. Update Baseline Dynamically
```bash
python backend/app/evals/run_eval.py --update-baseline
```
> [!IMPORTANT]
> `baseline.json` is generated directly by `run_eval.py` from actual pipeline measurements. It must never be hand-edited with hardcoded values.
